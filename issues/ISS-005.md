# ISS-005: Make Writer reject invalid XML documents

## Metadata
- Type: bug
- Status: closed
- Priority: 1
- Labels: writer, validation, breaking-api
- Assignee: codex
- Created: 2026-07-13
- Updated: 2026-07-13
- External ref: none

## Description
Writer directly concatenates names, comments, CDATA, processing instructions, and element boundaries. It can silently return text that Reader and conforming XML parsers reject.

## Design
Change Writer operations to a checked API with a public `WriterError`. Validate XML names and characters, forbidden delimiter sequences, document structure, and completion. Since the package is pre-1.0, replace the unsafe API directly instead of preserving compatibility wrappers.

## Acceptance Criteria
- [x] Invalid names, characters, comment text, CDATA text, and processing-instruction text are rejected.
- [x] Mismatched elements, multiple roots, and incomplete documents are rejected.
- [x] Existing valid Writer use cases remain supported through the checked API.
- [x] The public specification and generated interface reflect the new errors.
