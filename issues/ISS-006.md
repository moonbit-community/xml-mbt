# ISS-006: Retain useful structural parse-error spans

## Description
Parse errors now carry `SourceSpan`, but structural errors at end of input can report only a zero-width EOF range because the reader retains element names without their opening spans. Other syntax errors represent the consumed detection range rather than necessarily the exact offending token.

## Design
Retain opening element spans on the stack and use the unmatched opener for unclosed-element errors. Keep consumed detection ranges for general syntax errors and document that contract accurately.

## Acceptance Criteria
- [ ] An unclosed element error identifies the unmatched opening tag span.
- [ ] Matching and mismatched end-tag behavior remains correct.
- [ ] Documentation distinguishes structural-origin spans from consumed detection ranges.
